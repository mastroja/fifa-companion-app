# v3.0.0 Features

Running backlog — update statuses and details here as items are refined, adjusted, or completed. Use `[x]` for done, `[~]` for in progress.

- [ ] **Mobile companion (read-only)** — check squad, results, upcoming fixtures, and league standings from a phone/iPad without the desktop app open (PC still has to be on and running the game + this app for the data to be fresh).
  - Discussed 2026-09-13: the app already has the plumbing for this. `connected_career/firebase_client.js` uses the Firebase Web SDK with Anonymous Auth against a Realtime Database (free Spark tier, security rules scoped per code — no user accounts needed) for the existing two-person co-op career sync. The same pattern — desktop pushes a slice of its data up to Firebase after each sync/export, a separate client just reads it — is the natural blueprint here.
  - **Recommended first cut: a mobile-friendly web page, not a native app.** A true native app (App Store, home-screen icon) means a second codebase in a different framework (React Native/Expo) plus its own build/release pipeline. A simple responsive web page hosted somewhere (Firebase Hosting, Vercel, etc.) that reads the same Firebase data can reuse a lot of the existing card/UI styling from `index.html`, and gets bookmarked to the phone's home screen — most of the "feels like an app" benefit for a fraction of the effort. Only worth revisiting native later if push notifications or an actual App Store listing become a real want.
  - Needs: deciding what data slice to mirror up (squad, calendar/results, league standings at minimum), a security-rules review before exposing career data to a second unauthenticated-by-default surface (the existing rules are scoped for the two-person co-op case, not a public read endpoint), and a decision on hosting for the web page itself.
